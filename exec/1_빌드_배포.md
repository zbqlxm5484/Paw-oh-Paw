## 1.2 환경 변수

실제 값은 저장소에 없다. 서버에서는 GitLab CI/CD 변수(파일 형식)에 `.env` 전체를 넣어 두고 배포 때 복사한다.

### GitLab CI/CD 변수

| 이름 | 형식 | 내용 |
| --- | --- | --- |
| `ENV_FILE` | File | 운영 `.env` 전체 |
| `ENV_FILE_DEV` | File | 개발 `.env` 전체 |
| `GPU_DEPLOY_FREEZE` | Variable | `1`이면 분석 API 배포를 건너뛴다 |

### 팀 서버 `.env` (저장소 루트, 예시는 `.env.example`과 `backend/.env.example`)

기동에 꼭 필요한 값이다. 없거나 틀리면 API가 뜨지 않는다.

| 이름 | 예시 | 설명 |
| --- | --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `creamoff`, `creamoff`, (비밀) | postgres 컨테이너 초기화 값 |
| `DATABASE_URL` | `postgresql+pg8000://creamoff:<비밀번호>@postgres:5432/creamoff` | 드라이버는 pg8000만 받는다. 컨테이너 안에서는 호스트명이 `postgres` |
| `JWT_SECRET` | (비밀) | 32자 이상 |
| `FILE_URL_SECRET` | (비밀) | 32자 이상, `JWT_SECRET`과 다른 값 |

비밀값은 `python -c "import secrets; print(secrets.token_urlsafe(48))"`로 만든다. 운영과 개발은 서로 다른 값을 쓴다.

서버에서 기본값을 바꿔야 하는 값이다.

| 이름 | 기본값 | 서버 값 |
| --- | --- | --- |
| `ANALYSIS_API_MODE` | `mock` | 운영 `http`, 개발 `mock` |
| `ANALYSIS_API_BASE_URL` | 없음 | `http://host.docker.internal:18010` (`http`일 때 필수) |
| `ANALYSIS_API_KEY` | 없음 | GPU 서버 `~/service/env`의 `ANALYSIS_API_KEY`와 같은 값 |
| `CORS_ORIGINS` | `http://localhost:5173` | 안드로이드 앱의 `https://localhost`를 넣는다 |
| `FRONTEND_BASE_URL` | `http://localhost:5173` | `https://<도메인>/web` (비밀번호 재설정 링크의 앞부분) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | 비어 있음 | 재설정 메일을 보낼 때만. 비우면 재설정 요청이 503 |
| `UPLOAD_MAX_MB` | 100 | nginx `client_max_body_size`, GPU 서버 `ANALYSIS_UPLOAD_MAX_MB`와 같은 값 |
| `METRICS_ENABLED` | `false` | Prometheus로 볼 때 `true` |
| `API_DOCS_ENABLED` | `false` | 배포에서는 `false` |

나머지(워커 주기, 분석 줄 상한, 보고서 동시 생성 수 등)는 기본값으로 돈다. 전체 목록과 뜻은 `backend/.env.example`에 있다.

`REPORT_RENDERER_URL`, `REPORT_PRINT_URL`은 `.env`에 적지 않는다. `compose.yaml`이 워커에 직접 넣는다.

배포 스크립트가 읽는 값이다(CI가 넣어 준다).

| 이름 | 운영 | 개발 |
| --- | --- | --- |
| `COMPOSE_PROJECT` | `creamoff` (기본) | `creamoff-dev` |
| `NGINX_PORT` | 8080 (기본) | 8082 |
| `PUBLIC_URL` | `http://127.0.0.1:8080` (기본) | `http://127.0.0.1:8082` |

## 1.3 빌드와 배포 순서

### 팀 서버에 처음 띄우기

필요한 것: Docker와 Docker Compose가 설치된 Linux 서버, 도메인과 인증서.

```bash
git clone https://lab.ssafy.com/s15-final/S15P31A404.git
cd S15P31A404
cp .env.example .env        # 1.2의 값을 채운다
bash infra/ci/deploy.sh
```

`docker compose up`만으로는 API와 화면이 뜨지 않는다. 두 서비스가 `bluegreen` 프로필에 있어서 `deploy.sh`가 이름을 지정해 올린다.

`deploy.sh`가 하는 일이다.

1. postgres, redis, gotenberg를 띄운다.
2. 쉬고 있는 색(blue 또는 green)의 API와 화면 이미지를 빌드한다.
3. `alembic upgrade head`로 DB를 최신으로 맞춘다.
4. 새 색을 띄우고 상태 확인을 기다린다.
5. nginx가 새 색을 보게 바꾼다.
6. `/api/v1/health`와 `/`를 불러 본다. 실패하면 이전 색으로 되돌린다.
7. 워커를 새 코드로 다시 만든다.
8. 이전 색을 내린다.

확인한다.

```bash
curl http://127.0.0.1:8080/api/v1/health      # {"status":"ok","db":"ok",...}
docker compose -p creamoff ps
```

첫 관리자 계정을 만든다. 배포 스크립트에는 이 단계가 없다. 비밀번호는 화면에서 두 번 묻는다.

```bash
docker compose -p creamoff -f compose.yaml run --rm --no-deps api-blue \
  python -m scripts.seed --institution-code CREAMOFF --institution-name "크림오프" \
  --login-id <아이디> --name <이름> --role ADMIN
```

병원 담당자 계정은 관리자가 웹의 관리 화면(`/web/admin`)에서 **기관 추가**, **코드 발급**을 누르고, 담당자가 그 코드로 직접 가입한다.

### 바깥 주소 연결 (호스트 nginx)

컨테이너의 nginx는 `127.0.0.1:8080`에만 열린다. 호스트의 nginx가 80/443을 받아 넘긴다. 이 설정 파일은 저장소에 없으므로 서버에서 직접 만든다. 아래는 예시다.

```nginx
server {
    listen 443 ssl;
    server_name <도메인>;
    ssl_certificate     /etc/letsencrypt/live/<도메인>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<도메인>/privkey.pem;

    client_max_body_size 100m;          # 기본 1m이면 영상 업로드가 막힌다

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

주소가 나뉘는 방식: `/api/`는 팀 서비스 API, `/web/`은 병원용 웹, 나머지는 촬영 앱이다.

### GitLab CI로 배포하기

파이프라인은 check → build → smoke → deploy 순서다(`.gitlab-ci.yml`).

| 환경 | 브랜치 | 배포 | compose 프로젝트 | 포트 |
| --- | --- | --- | --- | --- |
| 운영 | `master` | 사람이 `deploy_prod`를 눌러야 나간다 | `creamoff` | 8080 |
| 개발 | `develop` | 머지하면 자동 | `creamoff-dev` | 8082 |

프로젝트 이름이 달라 DB와 업로드 볼륨이 서로 분리된다.

### 분석 API (GPU 서버)

GPU 서버에 미리 있어야 하는 것이다. 배포는 이것들을 건드리지 않는다.

| 위치 | 내용 |
| --- | --- |
| `~/venv/creamoff` | PyTorch, MMPose가 설치된 가상환경 |
| `~/models/company-orig` | 모델 코드와 가중치. 크림오프 자료라 저장소에 없다 |
| `~/service/env` | 환경 변수 파일 |
| `~/service/start.sh` | `env`를 읽고 `uvicorn main:app`을 8010에 띄우는 실행 스크립트 |

배포는 두 경우에 CI가 한다(`deploy_gpu`, 스크립트는 `infra/ci/deploy_gpu.sh`).

- `v`로 시작하는 보호된 태그를 붙였을 때
- `master`에 머지됐고 `analysis_api/`, `engine/`이 바뀌었을 때

스크립트는 소스를 `~/service/releases/<이름>/`에 복사하고, 의존성을 설치하고, `~/service/current` 링크를 바꾼 뒤 다시 켠다. `http://127.0.0.1:8010/health`가 `ok`가 아니면 이전 버전으로 되돌린다.

손으로 할 때는 GPU 서버에서 저장소를 받은 뒤 아래를 돌린다.

```bash
bash infra/ci/deploy_gpu.sh v1.0.0
```

### 팀 서버와 GPU 서버 잇기

GPU 서버는 밖에서 들어갈 수 없어서, GPU 서버가 EC2로 SSH 역방향 터널을 연다. EC2 호스트의 `172.18.0.1:18010`이 GPU 서버의 `8010`으로 이어진다. API와 워커 컨테이너는 이 주소를 `host.docker.internal`이라는 이름으로 부른다(`compose.yaml`의 `extra_hosts`).

## 1.4 배포 시 특이사항

- **워커는 한 대만 둔다.** 작업 큐가 DB라서 두 대면 같은 촬영을 같이 가져간다. 그래서 blue-green으로 나누지 않는다.
- **업로드 한도는 네 곳을 같게 맞춘다.** `UPLOAD_MAX_MB`, 컨테이너 nginx와 호스트 nginx의 `client_max_body_size`, GPU 서버의 `ANALYSIS_UPLOAD_MAX_MB`. 분석 API 쪽이 작으면 올리기는 되는데 분석 제출이 실패한다.
- **Docker 네트워크를 지우고 다시 만들면 터널이 끊긴다.** 게이트웨이 주소(`172.18.0.1`)가 바뀌면 터널의 주소, 방화벽 규칙, `authorized_keys`의 허용 주소를 같이 바꾼다.
- **`master`에 머지하면 분석 API도 같이 나간다.** 막으려면 CI 변수 `GPU_DEPLOY_FREEZE`를 `1`로 둔다. `develop` 머지로는 분석 API가 나가지 않는다.
- **분석 모드(`mock` ↔ `http`)는 진행 중인 촬영이 없을 때 바꾼다.** 진행 중이면 그 촬영은 시간 초과로 끝난다.
- **분석 API를 다시 켜면 분석 중이던 작업은 실패로 바뀐다.** 화면에서 다시 분석을 누르면 된다.
- **워커는 계약이 끝난 지 90일이 지난 기관의 자료를 자동으로 지운다.** 되돌릴 수 없다. 옛 DB를 복원해 띄울 때는 워커를 켜기 전에 아래로 대상을 본다.

  ```sql
  SELECT id, code, name, contract_ends_at FROM institution WHERE contract_ends_at < current_date - 90;
  ```

- **시연 데이터의 날짜는 넣은 날 기준이다.** 홈의 '오늘'을 채우려면 시연 당일에 다시 넣는다(`python -m scripts.seed_demo --data <폴더> --reset`). 넣기 전에 DB를 백업한다.
- **앱 서명 키를 바꾸면 QR로 앱이 열리지 않는다.** `frontend/public/.well-known/assetlinks.json`의 지문을 새 키의 것으로 바꾼다.
- **Windows에서 백엔드를 돌릴 때**: `alembic.ini`에 한글을 넣으면 명령이 멈춘다. 보고서 PDF는 GTK 런타임이 있어야 만들어진다.

| `backend/alembic.ini`, `backend/alembic/env.py`, `backend/alembic/versions/` | DB 마이그레이션 (0001~0023). 주소는 `DATABASE_URL`에서 읽는다 |
| `backend/config/breeds.yaml`, `backend/config/tolerance.yaml` | 견종 목록, 오차 범위 기준 |
| `backend/messages/ko.yaml` | 오류 문구 |
| `compose.yaml` | 컨테이너 구성, 볼륨, 워커의 보고서 렌더러 주소 |
| `infra/docker/nginx.conf` | 주소별 넘김 규칙, 업로드 한도 |
| `infra/ci/deploy.sh`, `infra/ci/deploy_gpu.sh`, `.gitlab-ci.yml` | 배포 스크립트와 파이프라인 |
| `frontend/.env.example`, `frontend/.env.android.example` | 촬영 앱 빌드 값 |
| `frontend/capacitor.config.ts`, `frontend/public/.well-known/assetlinks.json` | 안드로이드 앱 설정, 앱 링크 지문 |
| `analysis_api/models.yaml` | 쓸 수 있는 모델 목록과 기본 모델 |
| GPU 서버 `~/service/env`, `~/service/start.sh` (저장소에 없음) | 분석 API 환경 변수와 실행 스크립트 |
| `infra/monitoring/.env` (저장소에 없음), `infra/monitoring/compose.yaml` | Grafana 관리자 계정, 모니터링 구성 |
