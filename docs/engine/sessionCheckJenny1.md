# 실제 영상 보행 수치 검증: 제니 1회차

작성 조유진 · 11-11 (S15P31A404-261) · 도구 `engine/session_check.py` · 테스트 `tests/test_session_check.py`

제니(9.8kg)의 08-20 촬영을 회차 하나로 묶어, 팀 서비스가 보고서에 싣는 회차 값이 어떻게 나오는지와 수치끼리 서로 맞는지 본다. 지금까지는 통과 하나씩 재 보았고(`gaitMetrics.md` 4절, `jointRom.md` 5절), 회차로 묶어 보거나 영상과 맞춰 본 적은 없었다.

## 0. 결론

- **회차 값은 나온다.** 오른쪽 다리(카메라 쪽)는 유효 통과 25개로 모든 수치가 나왔다. 통과 사이 변동계수(CV)는 8에서 15%다(2절)
- **착지는 맞고 이지는 1프레임 일찍 잡는다.** 영상을 프레임마다 넘겨 보니 착지 3번은 1프레임 안, 이지 3번은 모두 1프레임 일렀다(30fps). 박규원의 사람 표시 대조(60fps에서 2프레임)와 같은 크기다(3.1)
- **속보가 아닌 통과 하나가 회차 값에 섞인다.** 260820-144421은 앞·뒷발 위상이 0.12로 속보(0.5)가 아니다. 카메라 4대에서 다 같아 관절점 문제가 아니라 그 통과의 걸음이다. 보행 유형 판별이 없어 지금은 걸러지지 않는다. 빼면 걸음 길이 CV가 9.8에서 6.9%로 준다(3.3)
- **발 높이는 들림 하나짜리 통과에서도 튀지 않았다.** 앞발 통과 24개 중 23개가 들림 하나인데, 통과 값이 19.6에서 28.9로 고르다(S15P31A404-259 MR 리뷰 2번 확인, 3.4)
- **GPU 서버와 오프라인 관절점의 차이(중앙값 2px)는 수치에 작다.** 걸음 길이 약 3, 발 높이 약 0.8, 가동 범위 1에서 2°로 통과 사이 흔들림보다 작다(3.5)
- **왼쪽 다리는 잴 수 없다.** 유효 통과 26개 중 왼쪽은 1개(0.33초)뿐이다. 이 회차는 한 방향으로만 찍혔다(3.6)

## 3. 서로 맞는지

### 3.1 영상으로 본 착지·이지 (260820-144517)

통과 하나(프레임 108에서 174, 오른쪽으로 감)의 착지·이지 프레임 앞뒤 2프레임을 발끝 둘레로 잘라 넘겨 보았다(영상 프레임은 저장소에 없음).

| 발 | 검출 | 영상에서 본 것 | 차 |
| --- | --- | --- | --- |
| 앞발 착지 | 132 | 131에서 132 사이에 발바닥이 매트에 닿음 | 0에서 +1 |
| 앞발 이지 | 139 | 139는 발끝이 아직 닿아 있고 140에서 떨어짐 | 1프레임 이름 |
| 앞발 착지 | 147 | 147에 닿음 | 0 |
| 앞발 이지 | 154 | 154는 발끝이 닿아 있고 155에서 떨어짐 | 1프레임 이름 |
| 뒷발 이지 | 131 | 131은 닿아 있고 132에서 떨어짐 | 1프레임 이름 |
| 뒷발 착지 | 140 | 140에 닿음 | 0 |
| 뒷발 이지 | 146 | 146은 발끝이 닿아 있고 147에서 떨어짐 | 1프레임 이름 |
| 뒷발 착지 | 155 | 154에서 155 사이 | 0에서 −1 |

- 엔진은 발끝이 느려지고 빨라지는 것으로 디딤을 잡는다. 발꿈치가 들리고 발끝만 닿아 있는 마지막 프레임에 발끝이 이미 움직이기 시작해, 이지를 그 프레임으로 잡는다
- 30fps 1프레임(33ms)은 60fps 2프레임이다. 박규원의 사람 표시 대조(`gaitMetrics.md` 4절, 60fps에서 이지 중앙값 −2프레임)와 같은 크기다
- 그래서 입각기 비율은 한 주기 14프레임 중 1프레임, 약 7%p 작게 나온다. 이지 보정은 표시 기준을 맞춘 뒤 정한다(`gaitMetrics.md` 6절)

### 3.2 걸음 길이와 보행 속도

일정하게 걸으면 걸음 길이 = 보행 속도 × 한 주기 시간이다. 주기를 잰 통과마다 둘의 비율을 냈다.

| 관절점 | 비율 중앙값 |
| --- | --- |
| `fs-v4` | 0.93 |
| `fs-v4-flip` (카메라 4대) | 0.96 |

- 걸음 길이가 보행 속도로 계산한 값보다 4에서 7% 작다. 걸음 길이는 디딤 자리(발끝 좌표의 중앙값) 사이 거리이고, 보행 속도는 몸통 가운데의 측정 구간 속도 중앙값이라 잰 곳과 구간이 다르다
- 어느 쪽이 맞는지는 사람이 표시한 착지 발끝 위치(KPI-06)가 있어야 가린다. 지금은 차이가 있다는 것만 적는다

### 3.3 속보가 아닌 통과 (260820-144421)

| 값 | 이 통과 | 나머지 통과 중앙값 |
| --- | --- | --- |
| 앞·뒷발 위상 | 0.12 | 0.47 (주기를 잰 통과) |
| 보행 속도 (L/초) | 4.2 | 8.1 |
| 입각기 비율 앞·뒤 (%) | 57.9 · 55.0 | 42.9 · 35.7 |
| 걸음 길이 앞·뒤 (`pct_body`) | 247.4 · 264.9 | 355.5 · 374.2 |

- 위상은 같은 쪽 뒷발 착지에서 가장 가까운 앞발 착지까지의 시간 ÷ 주기다. 측대보 0, 평보 0.25, 속보 0.5 근처다. 0.12는 측대보에 가까운 느린 걸음이다
- `fs-v4-flip`의 같은 촬영 카메라 4대가 0.10에서 0.16으로 같다. 관절점이 튄 것이 아니라 그 통과의 걸음이다
- 유효 판별은 측대보(`GAIT_PACE`)를 위상으로 거르지 않고, 결과의 `gait`는 아직 null이다(보행 유형 판별 전, 결과 형식 6절). 그래서 이 통과가 회차 값에 섞인다
- 중앙값이라 회차 값은 거의 그대로다(걸음 길이 앞 352.3 → 355.5). 통과 사이 CV는 걸음 길이 9.8 → 6.9%, 입각기 비율 뒤 15.4 → 8.6%, 보행 속도 13.3 → 8.8%로 준다
- 보행 유형 판별이 들어가면 이 통과가 `GAIT_OTHER`나 평보로 빠지는지 이 촬영으로 확인한다

### 3.4 발 높이: 들림이 하나뿐인 통과 (S15P31A404-259 MR 리뷰 2번)

통과 값은 들림들의 중앙값이라, 들림이 하나면 그 들림의 최댓값이 그대로 통과 값이 된다. 튄 점 하나가 값을 정하는지 보았다.

| 관절점 | 들림 하나뿐인 통과 앞·뒤 | 가장 높은 프레임 − 그다음 (L 대비 %) |
| --- | --- | --- |
| `fs-v4` | 23 / 24 · 17 / 21 | 중앙값 1.4, 최대 6.5 |
| `fs-v4-flip` | 56 / 62 · 53 / 60 | 중앙값 1.9, 최대 6.9 |

- 거의 모든 통과가 들림 하나다. 그래도 통과 값이 앞발 19.6에서 28.9로 고르고(CV 10.5%), 리뷰에서 든 경우(9.8이 24.9로)처럼 두 배 넘게 튄 통과는 없다
- 가장 높은 프레임과 그다음의 차는 대개 1에서 2%다. 들림 하나가 30fps에서 9프레임 안팎이라 꼭대기 근처에 프레임이 둘 이상 있다
- 차가 6.5%인 들림이 있어, 튄 점 하나가 값을 3에서 6% 올리는 일은 있을 수 있다. 정의는 "최대 들림"이라 최댓값을 그대로 두고, 다른 개·날 영상에서 차가 커지면 위 두 프레임의 평균으로 바꿀지 정한다

### 3.5 GPU 서버 관절점과의 차이가 수치에 주는 크기

GPU 서버 점검(`docs/analysisApi/gpuCheck.md` 3절)에서 서버 관절점과 오프라인 관절점의 차는 중앙값 2.1에서 2.6px였다. 오른쪽 유효 통과 25개의 관절점에 표준편차 2px 흔들림을 다섯 번 넣고 수치가 얼마나 바뀌는지 보았다.

| 수치 | 바뀐 크기 중앙값 | 90% 지점 | 측정 가능 여부가 바뀐 통과 |
| --- | --- | --- | --- |
| 걸음 길이 앞·뒤 (`pct_body`) | 2.8 · 3.3 | 6.1 · 6.2 | 0 / 125 |
| 입각기 비율 앞·뒤 (%) | 0 · 0 | 3.3 · 5.7 | 0 / 125 |
| 발 높이 앞·뒤 (`pct_body`) | 0.8 · 0.8 | 1.8 · 2.3 | 0 / 125 |
| 보행 속도 (L/초) | 0.08 | 0.21 | 0 / 125 |
| 가동 범위 무릎 · 고관절 · 팔꿈치 (°) | 1.3 · 2.1 · 1.7 | 3.2 · 5.9 · 4.3 | 0 / 125 |

- 모두 통과 사이 흔들림(2절 CV)보다 작다. 입각기 비율은 가끔 1프레임(약 7%p)씩 바뀐다
- 실제 차는 프레임마다 아무렇게나가 아니라 입력 크기 차이처럼 한쪽으로 치우칠 수 있어, 서버 결과로 같은 표를 다시 내는 것이 정확하다(4절)

### 3.6 왼쪽 다리

- 왼쪽으로 지나간 유효 통과는 260820-150448의 두 번째 통과 하나다. 몸 전체가 보인 시간이 0.33초라 걸음 길이·입각기 비율·발 높이가 다 측정 불가였고, 가동 범위와 보행 속도만 나왔다
- 그 통과는 몸통 길이가 316px로 다른 통과(156에서 189px)의 두 배 가깝다. 돌아올 때 카메라에 훨씬 가까이 지나갔다
- 그래서 이 회차의 보고서는 왼쪽 다리가 `NO_PASS_FOR_LIMB`나 측정 불가이고, 좌우 비교(대칭 지수)가 나오지 않는다. 시연·기업 촬영 안내에 "같은 선으로 양쪽 방향을 방향별 8번"을 넣어야 한다

## 4. 한계

2. 관절점은 오프라인으로 뽑은 것이다. GPU 서버가 낸 결과로 같은 표를 낸 것이 아니다. 서버 결과는 점검 3개 영상만 있다(3.5)

4. 3.1의 영상 확인은 통과 하나, 사건 8번이다
