## 3. 보임·가림(Q) 규칙

### 3-1. 기본

- **카메라 쪽 다리**: 거의 다 보여요. 정답에서도 카메라 쪽 점에 Q가 켜진 건 귀 1건뿐이에요.
- **반대쪽 다리**: 몸통 뒤라서 점마다 달라요. 위치는 반드시 찍고(비워 두지 않음), 그 점이 지금 화면에서 **눈에 보이는지**만으로 Q를 정해요.
- 카메라 쪽 판정은 가이드 3장대로 해요. 개가 화면 오른쪽을 보면 오른쪽 다리, 왼쪽을 보면 왼쪽 다리가 카메라 쪽이에요. **카메라 이름(main·sub1…)으로 정하지 마세요.** 개가 매트를 오가니까 같은 카메라에서도 보이는 면이 바뀌어요.

### 3-2. 반대쪽 다리는 보통 이렇게 나온다

가이드를 따라 표시한 정답(`eval` 묶음 64장)에서 반대쪽 점에 Q가 켜진 비율이에요. **할당량이 아니고, 감을 잡으라고 보여 주는 참고값이에요.**

| 반대쪽 점 | Q 켜진 비율 | 감 |
|---|---|---|
| 귀 | 94% | 거의 항상 Q |
| 어깨뼈 위끝 | 80% | 대부분 Q |
| 어깨 | 81% | 대부분 Q |
| 고관절 | 75% | 대부분 Q |
| 무릎 | 45% | 그때그때 |
| 뒷발목 | 33% | 그때그때 |
| 팔꿈치 | 11% | 대부분 보임 |
| 뒷발끝 | 5% | 거의 보임 |
| 앞발목 | 3% | 거의 보임 |
| 앞발끝 | 0% | 보임 |

몸통에 붙은 위쪽 관절(어깨·고관절)은 대부분 가려지고, 배 아래로 나온 아래쪽(발목·발끝)은 다리 사이로 보여요.

### 3-3. 정답 파일에 섞인 두 규칙 (중요)

기업 정답에는 **표시 규칙이 다른 두 묶음**이 섞여 있어요.

| 묶음 | 건수 | 반대쪽 어깨뼈·어깨·고관절 |
|---|---|---|
| `seed` | 141 | **Q 0%** (366개 모두 '보임') |
| `eval` | 64 | Q 79% (151 / 192) |
| `rep` | 16 | Q 85% (41 / 48) |

`seed`는 반대쪽이 몸통에 가려졌는데도 '보임'(2)으로 들어가 있어요. 기업 README는 "visibility 2만 채점"하라고 하는데, 그대로 따르면 `seed`에서는 **추정한 반대쪽 어깨·고관절이 정답처럼 채점돼요.** 어깨각·고관절각(KPI-04)이 그 점을 꼭짓점으로 쓰니까 영향이 바로 가요. 가이드의 22점 그림도 반대쪽 어깨(3·4)에 Q가 없어서, `seed` 쪽 습관이 남아 있는 것으로 보여요.

- **우리 라벨은 `eval` 규칙(가이드 본문)을 따라요.** 보이지 않으면 Q를 켜요.
- 평가할 때는 `seed`의 반대쪽 점을 빼거나 `eval`만 쓰는 쪽을 제안해요. 모델 담당과 정하고 기업에 확인할 일이에요(6장).

## 4. 애매한 경우

가이드 7장 판단표가 기본이에요. 우리 데이터에서 자주 나올 것만 덧붙여요.

| 상황 | 할 일 |
|---|---|
| **대형견이 화면 끝에 걸려** 발이나 머리가 잘림 | 잘린 점은 추정하지 말고 **O(화면 밖)**. 화면 안에 있지만 일부만 보이면 Q. grade `ambiguous` + `화면걸침`, 거의 안 보이면 `unusable` |
| 반대쪽 다리가 카메라 쪽 다리와 **겹쳐** 어느 쪽인지 모름 | F·D로 앞뒤 장을 넘겨 다리가 갈라지는 장에서 이어 찍어요. 그래도 모르면 Q + `ambiguous` + `다리겹침`. **좌우를 바꿔 찍는 실수가 가장 비싸요**(KPI-21·24) |
| 발이 땅에 닿는지 떠 있는지 애매함 | 위치만 정확히 찍어요. 닿음·뜸은 이 라벨에서 정하지 않아요 |
| 털이 길어 관절이 묻힘 | 보이는 털 윤곽이 아니라 **관절이 있을 자리**를 찍고, 보이는 면이면 Q는 꺼요. `ambiguous` + `기타`(털) |
| 흐림(빨리 움직임) | Q 끔. `ambiguous` + `흔들림` (가이드와 같음) |
| 오토라벨이 2·13번을 이상한 데 찍음 | 옮기지 않아요. 크게 벗어났으면(몸 밖 등) reason `기타`에 "2번 이탈"처럼 적어요 |

판단 기준은 가이드와 같아요. "지금 그 부위를 눈으로 보고 있는가, 추측하고 있는가."

## 5. 라벨링 방식 두 가지 (11-06)

오토라벨(fs-v4)이 깔린 사진에서 시작해요. 같은 기준(이 문서·labeler.md)으로 찍되, **얼마나 손보는지**만 달라요. 인수 시험에서 어느 쪽이 나은지 비교해요.

| 방식 | 할 일 | 장당 시간 | 장당 고친 점(실측) |
|---|---|---|---|
| **A. 꼼꼼히** | 22점을 하나씩 보고, 기준에서 벗어난 점은 작은 차이라도 옮겨요. Q·O·grade 도 전부 확인 | 3~5분 | 평균 9.7점 |
| **B. 크게 틀린 점만** | 한눈에 틀린 점(다른 관절에 찍힘, 좌우 바뀜, 몸 밖)만 옮기고 나머지는 그대로 둬요. grade 는 꼭 남겨요 | 1분 안쪽 | 평균 6.2점 |

'고친 점' = 오토라벨에서 상자 대각선의 2% 넘게 옮긴 점(22점 중). A안 team300 278장, B안 teamB 145장에서 쟀어요(11-10).

같이 지킬 것

- 다른 사람 결과는 끝날 때까지 보지 않아요(사람마다 차이를 잴 때).
- **좌우를 바꿔 찍는 실수가 가장 비싸요.** B 방식이라도 좌우가 바뀐 점은 꼭 고쳐요.
- 쓸 수 없는 장은 grade `unusable` 로 표시하면 학습에서 빠져요. 억지로 찍지 않아요.

## 7. 학습 파일로 바꿀 때 지킬 것 (11-10)

CVAT 백업 zip → 학습용 COCO 는 `team300_1106/backups_to_coco.py` 방식으로 바꿔요.

- **가려진 점(Q)은 visibility 1 로 남겨요. 0 으로 지우지 않아요.** 11-10 에 와우와우 일부 묶음이 예전 실험용 변환(가려진 점 → 0)을 거친 파일로 학습돼, 같은 학습에서 묶음마다 규칙이 섞였어요. 화면 밖(O)만 0 이에요.
- 점 수는 학습 설정에 맞춰요(지금 학습은 46칸, 22점 뒤 24칸은 0). 22점 파일을 그대로 섞으면 학습이 멈춰요.
- grade `unusable` 은 빼고, `unreviewed` 는 경고만 하고 넣어요(필요하면 빼는 옵션).
- 누가 언제 어떤 묶음을 했는지는 라벨 모음 README 에 적어 둬요(내려받은 원본과 같이 보관, 라벨링 안 된 원본은 보관하지 않아요).
