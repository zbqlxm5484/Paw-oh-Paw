# GPU 서버 분석 API 점검 기록

작성 조유진 · 11-10 (S15P31A404-258) · 스크립트 `analysis_api/check_server.py` · 사용법 `analysis_api/README.md`

GPU 서버에 배포한 분석 API를 팀 서비스 워커와 같은 순서(등록 → 2초마다 상태 조회 → 결과·관절점 파일 받기 → 지우기)로 불러, 결과가 결과 JSON v1(`resultFormat.md`) 모양인지와 걸린 시간을 확인했다. 같은 영상의 미리 뽑은 관절점과도 비교했다.

## 1. 환경

| 항목 | 값 |
| --- | --- |
| 서버 | SSAFY GPU 서버 (JupyterLab 터미널, 서버 안 주소 `http://127.0.0.1:8010`) |
| 배포 | 배포 태그 `v0.0.2-model`(11-06, 모델 모드 S15P31A404-229까지). GPU 서버 배포는 `v*` 태그를 찍을 때만 돈다(S15P31A404-239). 이 MR의 시간 제한·촬영 단위 지우기는 점검 당시 서버에 없었고, 점검 스크립트만 따로 올려 돌렸다 |
| `/health` | `status: ok`, 모델 `fs-v4`, `pose_source: model`, `model_known: true` |
| `model.version` | `0.6.0/v1/a4261a10` |
| 영상 | 기업 제니 영상(260820, main 카메라, 1920×1080, 30fps) 3개 |
| 비교 관절점 | `fs-v4.track.json` (박규원, 기업 `video_kpi.py`, GPU, 입력 높이 768) |

영상·관절점 파일은 기업 데이터라 저장소에 없다. 점검이 끝난 뒤 서버에 올린 사본과 분석 작업은 지웠다.

## 3. 미리 뽑은 관절점과 비교

| 영상 | 개를 찾은 프레임 (서버 / 미리 뽑은 것) | 관절점 위치 차 중앙값 | 95% 지점 |
| --- | --- | --- | --- |
| `260820-141844` | 49 / 48 | 2.14px | 9.78px |
| `260820-150448` | 118 / 119 | 2.56px | 12.14px |
| `260820-144036` | 39 / 39 | 2.23px | 10.74px |

- 위치 차는 두 쪽 모두 확신도 0.3 이상인 관절점끼리 잰 거리다. 몸통 길이(이 영상들에서 150에서 180px)로 나누면 중앙값 약 1.5%, 95% 지점 약 7%다
- 완전히 같지는 않다. 미리 뽑은 관절점은 기업 평가 스크립트(`video_kpi.py`)로 영상을 높이 768로 줄여 돌렸고, 서버는 기업 `run.py` 경로로 돈다. 입력 크기·전처리 차이와 GPU 연산 차이가 겹친 것으로 보이며, 어느 몫이 큰지는 나누어 보지 않았다
- 개를 찾은 프레임은 통과 끝에서 1프레임씩만 다르고, 판정·통과 수는 같다. 수치 차이는 제니 실제 영상 검증(S15P31A404-261)에서 서버 결과 기준으로 다시 본다

## 4. 다시 점검하려면

`analysis_api/README.md`의 "떠 있는 서버 점검"을 따른다. GPU 서버 JupyterLab 터미널에서는:

```
cd <영상을 올린 폴더>
set -a; . $HOME/service/env; set +a
python3 check_server.py --url http://127.0.0.1:8010 --video <영상> --track <관절점 파일>
```

끝나면 올린 영상·관절점 파일을 지운다.
