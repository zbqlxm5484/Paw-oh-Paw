# 개 단위 학습/검증 분할 (10-20, S15P31A404-35)

같은 개의 옆 프레임이나 다른 카메라 영상이 학습과 검증에 같이 들어가면 검증 점수가 실제보다 좋게 나와요. 그래서 **개를 통째로 한쪽에만** 넣었어요.

- 스크립트: `ai/data_prep/split_by_dog.py`
- 결과 파일(개 → split, 촬영 stamp → split)은 기업 자료에서 나온 것이라 레포에 올리지 않아요. 아래 명령으로 다시 만들어요.
- 다시 돌리기: `python split_by_dog.py --manifest <dataset>/videos/manifest.csv --out <폴더> [--apply 정답.json ...]`
  - `--apply` 를 주면 COCO 파일을 split 별 파일로 나눠요. 촬영 번호는 `images[].session` 이나 파일 이름에서 읽어요(CVAT 백업 파일 이름도 돼요).

## 규칙

| 개 | split | 이유 |
|---|---|---|
| 제니 | `gt_eval` | 기업 정답 205장이 전부 제니예요. 재현·비교용으로 고정하고, 섞이지 않게 제니의 다른 영상도 학습에서 빼요 |
| dogA | `disease` | 질환견이라 정상 보행 학습·검증과 섞지 않아요. 기업 유무효 기준 문서에 따르면 `pace` 42건·`disease` 19건이 모두 dogA 한 날 촬영이에요 |
| 나머지 21마리 | `train` / `val` | 체급마다 **개 수의 30%** 를 val로 보내요(최소 1마리). 촬영이 가장 많은 개는 train에 두고, 나머지는 시드 42로 섞어서 골라요 |

- 체급: 10kg 미만 소형, 10~25kg 중형, 25kg 이상 대형 (manifest 교정 체중 기준)
- 촬영 수에서 calib·weight·_discard는 빼요. 단, 정답이 있는 260820 두 촬영은 _discard여도 남겨요(빼면 정답 24장이 사라져요)
- 촬영 수가 아니라 개 수로 맞춘 이유: 보려는 건 "처음 보는 개"에서의 성능이고, 학습 라벨은 개마다 골라서 만들 거라서요(S15P31A404-36)

알아 둘 점

- **대형견은 두 마리뿐이라** train·val에 한 마리씩이에요. 대형 val 점수는 개 한 마리 결과예요.
- 소형 val 4마리는 모두 대구한의대 촬영이에요(카메라 1대). 장소 차이와 개 차이가 섞여 있어요.
- 라벨 맞추기 20장 중 4장은 val 개 사진이에요. 그 4장은 일치도 측정에만 쓰고 학습에는 넣지 않아요.

## AI-Hub 71878과 합치는 규칙

- AI-Hub는 `aihub_to_coco.py`의 **세션 단위 분할**(반별 층화, 시드 42)을 그대로 써요. 옆 촬영만 남긴 파일(`filter_views.py`) 기준 train 43,870 / val 4,893 / test 6,168장(세션 716 / 91 / 92)이에요.
- 크림오프와 AI-Hub는 개가 겹치지 않아서 출처끼리는 누수가 없어요.
- **학습 = 크림오프 train + AI-Hub train.** 검증 점수는 출처별로 따로 내고, KPI 판단은 크림오프 val(과 gt_eval)로 해요.
- AI-Hub test는 마지막 확인용으로 남겨 둬요.
- AI-Hub 라벨에는 개 번호가 없어요(병원·견종·체급·나이만 있어요). 그래서 세션 단위가 최선이에요. 같은 개가 여러 세션에 있으면 AI-Hub 안에서는 누수가 남을 수 있어요.
