# 비스듬한 진행 감지 (10-26, S15P31A404-94)

개가 카메라 화면과 평행하지 않게 걸으면 2차원 정규화 값이 틀어져요. 통과마다 "비스듬함" 을 표시하는 함수를 만들었어요. 표시만 하고 통과를 버리지는 않아요(유효 판별 규칙 S15P31A404-21 과 겹치지 않게).

- 스크립트: `ai/normalize/oblique.py` (`normalize.py` 와 같은 통과 규칙·track 형식)
- 실행: `python oblique.py --track <video_kpi track.json> --out oblique.json --csv oblique.csv`, 확인 `python oblique.py --self-test`

## 재는 값

몸통 축 = 어깨 가운데(4·9) − 고관절 가운데(14·18). 상자가 화면 왼쪽·오른쪽 끝(1%)에 닿은 프레임은 몸이 잘려 몸통이 짧아 보이므로 빼요.

| 값 | 뜻 | 판정에 쓰나 |
|---|---|---|
| `path_deg` | 몸통 가운데 궤적이 화면 수평과 이루는 각 | 쓴다 (> 5°) |
| `yaw_change` | 몸통 길이 ÷ 상자 높이 의 통과 처음·끝 비 | 쓴다 (> 1.25) |
| `len_change` | 몸통 길이의 처음·끝 비 | 쓴다 (> 1.6) |
| `height_change` | 상자 높이의 처음·끝 비 (카메라와 거리 변화) | 참고 |
| `axis_deg` | 몸통 축 기울기 중앙값 | 참고 (자세에도 바뀜) |

핵심은 `yaw_change` 예요. 카메라와의 거리만 바뀌면 몸통 길이와 상자 높이가 같은 비율로 변해서 1 에 가깝게 남아요. 진행 방향이 화면과 비스듬하면 몸통만 짧아지거나 길어져요. 비는 모두 큰 쪽 ÷ 작은 쪽이라 1 이상이에요. 직선은 Theil-Sen 으로 맞춰서 튀는 프레임에 덜 흔들려요.

## 현행 모델 관절점 분포 (fs-v4 + flip, 260820 정답 원본 영상 72건, 통과 72개)

| 카메라 | 통과 | `yaw_change` 중앙 | 90% |
|---|---:|---:|---:|
| main | 18 | 1.22 | 1.50 |
| sub1 | 18 | 1.12 | 1.24 |
| sub2 | 18 | 1.06 | 1.18 |
| sub3 | 18 | 1.07 | 1.18 |

전체: `path_deg` 절댓값 중앙 0.72°·최대 3.28°, `len_change` 중앙 1.16·최대 1.81. 비스듬함 9개, 모두 `yaw` 때문이고 그중 main 이 대부분이에요.

눈으로 확인한 결과, main 이 높은 건 측정 오류가 아니에요. main 화면에서 매트가 사다리꼴로 보이고 개가 오른쪽으로 갈수록 작아져요. main 카메라가 매트와 비스듬하게 놓여 있는 거예요. sub2·sub3 는 거의 평행이에요.

## 문턱 정한 근거 (합성 카메라로 확인)

평행에 가까운 sub2·sub3 통과 36개에 `synth_camera.py` 로 카메라 회전만 넣고 다시 쟀어요.

| 넣은 변환 | `yaw_change` 중앙 | 비스듬함 표시 |
|---|---:|---:|
| 없음 | 1.06 | 2 / 36 |
| yaw ±5° | 1.42~1.51 | 33~34 / 36 |
| yaw ±10° | 1.62~1.75 | 36 / 36 |
| pitch ±10° | 1.05~1.06 | 0~2 / 36 |
| roll ±4° | 1.05 (`path_deg` 약 4°) | 1 / 36 |
| zoom 0.8 | 1.09 | 10 / 36 |

- `yaw_change` 1.25 는 평행 카메라(1.06)와 5° 회전(1.42) 사이예요. main 의 중앙값 1.22 는 회전 2~3° 정도에 해당해요.
- `path_deg` 5° 는 실제 촬영 최대(3.3°)보다 조금 위예요. roll 4° 를 넣으면 4° 정도 나와요.
- zoom 0.8(개가 작게 찍힘)은 관절점이 흔들려 잘못 표시되는 게 늘어요. 작은 개·먼 카메라에서 확인해야 해요.

## 비스듬한 통과 처리와 재측정 (10-29, S15P31A404-102)

처리 방법마다 같은 통과에서 KPI-01·02 를 다시 쟀어요(paw_eval `video_kpi.py` 규칙, 스크립트 `ai/experiments/normalize/oblique_fix.py`).
감소율은 정규화 없음 대비, +면 좋아짐이에요.

| 방법 | 실제 26개(KPI 기본 묶음) KPI-01 | 실제 72개 KPI-01 | 합성 yaw | 합성 pitch·roll·zoom | KPI-02 |
|---|---:|---:|---:|---:|---:|
| v0 (가로 늘리기 + 세로) | −14% | −7% | +4% | −13~−21% | 0~−10% |
| v0 + 비스듬한 통과만 기울기 보정 | −14% | −7% | +4% | 같음 | 같음 |
| v0 + 비스듬한 통과 제외 | −11% | −3% | +23% (통과 451 → 100) | −3~−6% | 0~−10% |
| **가로 늘리기 없이 거리만 보정(iso)** | **+7%** | **+4%** | **+21%** | **+4~+6%** | **0%** |

- v0 의 가로 늘리기는 몸통 길이로 비율을 정하는데, 세로로 선 다리 체절까지 가로로 늘려서 KPI-01(체절 길이 변동)이 오히려 커졌어요.
- 기울기 보정은 효과가 없어요. 실제 촬영 통과 중 `path` 로 걸린 것이 0개예요(비스듬함 9개 모두 `yaw`).
- 비스듬한 통과를 빼면 합성 yaw 에서는 좋아 보이지만 통과 대부분이 빠지고, 실제 촬영에서는 오히려 나빠져요.
- KPI-02(화면 왼쪽·오른쪽 1/3 각도 차)는 어떤 2차원 보정으로도 줄지 않아요. 10-19 정규화 v0 실험의 "KPI-02 는 화면 위치에 따른 실제 차이" 와 같은 결론이에요.

결정: 정규화를 **v1** 로 바꿔 기본을 iso(거리 변화만, 가로·세로 같은 비율)로 해요. 가로 늘리기는 `--stretch-x` 로만 켜요.
통과마다 비스듬함 측정값과 판정을 `passes[].oblique` 에 적고, 보정이나 제외는 하지 않아요.

공식 채점(`video_kpi.py score --compare`):

| 묶음 | 정규화 없음 KPI-01 CV | v0 | v1 | KPI-02 (없음 → v1) |
|---|---:|---:|---:|---:|
| fs-v4, 제니 main 26개 | 0.1240 | 0.1415 (−14%) | **0.1155 (+7%)** | 14.55° → 14.56° |
| fs-v4+flip, 제니 72개 | 0.1227 | 0.1316 (−7%) | **0.1172 (+4%)** | 15.61° → 15.60° |

PRD 목표(KPI-01 30% 감소, KPI-02 50% 감소)에는 둘 다 못 미쳐요. 2차원 기하 보정으로 줄일 수 있는 몫은 이 정도이고,
나머지는 관절점 흔들림(KPI-01)과 화면 위치에 따른 실제 차이(KPI-02)로 보여요.
