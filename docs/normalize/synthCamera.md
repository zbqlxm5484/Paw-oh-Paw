# 카메라 오차 합성 (10-26, S15P31A404-97)

카메라 위치·각도가 달라도 정규화한 수치가 같게 나오는지 시험하려고, 한 영상을 여러 "가짜 카메라" 로 다시 찍은 것처럼 만들어요.

- 스크립트: `ai/normalize/synth_camera.py`
- 영상까지: `python synth_camera.py --video a.mp4 --track a.track.json --out-dir out/ [--only yaw,roll] [--sample]`
- 관절점만: `python synth_camera.py --track a.track.json --out-dir out/ --points-only`
- 확인: `python synth_camera.py --self-test`

## 방식

변환은 모두 3×3 호모그래피 H 하나로 적고, 프레임(`cv2.warpPerspective`)과 관절점·상자에 똑같이 곱해요.

- yaw·pitch·roll(카메라가 제자리에서 도는 것): H = K R K⁻¹. 제자리 회전이면 이 식이 정확해요. K 의 초점 거리는 촬영 카메라 보정값(260826, main 715 · sub1 774 · sub2 727 · sub3 740 px @1920) 가운데인 745 px 이고, `--focal` 로 바꿔요.
- zoom: 화면 가운데 기준 확대·축소. 카메라 거리·화각 차이를 대신해요.
- shift_x·shift_y: 화면 안 위치 이동. 카메라 높이·좌우 위치 차이를 대신해요.
- 화면 밖으로 나간 관절점은 확신도 0, 상자는 네 꼭짓점을 변환해서 감싸요. 빈 곳은 검은색이에요.
- 렌즈 왜곡은 넣지 않았어요.

## 변환 범위 (실제 촬영 4대 차이 근거)

근거 자료: 260820 main·sub1~3 영상 72건(fs-v4 + flip 관절점), 화면 끝에 닿은 프레임은 뺌.

| 종류 | 값 | 실제 차이 |
|---|---|---|
| roll | −4, −2, +2, +4° | 통과 궤적 기울기가 카메라마다 −2.5~+3.3° |
| yaw | ±5, ±10, ±15° | main 이 매트와 비스듬함(회전 2~3° 정도, `docs/normalize/oblique.md`). 더 나쁜 설치를 보려고 15° 까지 |
| pitch | ±5, ±10° | 상자 가운데 높이가 화면 0.36~0.53 (카메라 높이·숙임 차이) |
| zoom | 0.8, 0.9, 1.1, 1.2 배 | 상자 높이가 화면의 0.28~0.40 (±20%) |
| shift_x | ±5% | 좌우 위치. 더 밀면 통과 시작·끝이 잘려요 |
| shift_y | ±4, ±8% | 상자 가운데 높이 차이 ±8% |

모두 22개 변환이에요. 실제보다 넓게 잡은 건 yaw 뿐이고, 나머지는 실제 범위 안이에요.

## 결과 파일

변환마다 `<원본 이름>.<종류><값>` 이름으로 세 파일을 만들어요.

- `.mp4`: 합성 영상 (원본과 같은 크기·fps)
- `.track.json`: 원본 관절점을 변환한 것. 합성 영상에서 모델이 다시 낸 관절점과 비교하는 기준이에요
- `.json`: 정답(종류, 값, 단위, 초점 거리, H 행렬, 프레임 수)

## 샘플 확인 (10-26)

260820-144421 sub3 영상에 종류마다 가장 큰 값 하나씩(roll −4°, yaw −15°, pitch −10°, zoom 1.2, shift_x −5%, shift_y −8%) 만들어 110번째 프레임에 변환한 관절점을 그려 봤어요. 6개 모두 관절점이 개를 따라가요. yaw −15° 는 화면 오른쪽에 큰 검은 영역이 생겨서, 탐지가 흔들리는지 측정 때 같이 봐야 해요.
