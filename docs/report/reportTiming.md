# 보고서 생성 시간 측정과 견본 PDF (S15P31A404-200)

작성 조영운 · 2026-11-04 측정 · F-08 보고서 에픽의 REPORT 산출물 (3/3)

- 무엇을: 보고서 모듈(백엔드 명세 8절)이 입력 JSON 하나로 PDF 한 판본을 만드는 시간(`generation_ms`, KPI-29)을 경우별·판본별로 잰다. 같은 스크립트가 D-08 견본 PDF 12부(경우 6 × 판본 2)를 만든다.
- 왜: 17.4 BE-15 "회차가 DONE이 된 뒤 두 판본이 20초 안에 DONE이 된다"(KPI-29). 워커는 보고서 풀 1개에서 두 판본을 잇따라 만들므로(12.4) 한 판본 생성 시간 × 2에 주 반복 주기(2초)를 더한 값이 기준이다.
- 어디에 반영: 백엔드 README 보고서 절, 11-10 시연 준비, 팀 서버에 워커가 생기면 같은 명령으로 재측정(199 배포 점검 항목).
- 다시 재는 법: `backend`에서 `python -m scripts.report_samples <폴더> --repeat 3 --pool`. 이 문서의 표는 그 출력이다. 견본 경우 목록은 `app/report/samples.py`.

## 0. 결론

- **한 판본은 이 PC에서 약 6초**(12부 중앙값 5.4~6.5초, 최대 6.8초). 그중 HTML 만들기(문장·표·차트 2장)는 0.2~0.4초이고 **WeasyPrint PDF 변환이 4.5~6초**로 거의 전부다. 수치가 0개인 2KB짜리 HTML도 5초가 걸려, 문서 크기가 아니라 글꼴 적재 같은 고정 비용이다(이 PC는 Windows의 GTK 런타임으로 돌린다).
- **두 판본은 풀 1개에서 잇따라 10.8~14.4초**(첫 경우 14.4초는 자식 프로세스의 첫 import를 포함). KPI-29 20초 안이다. 11-03에 서버·워커·DB로 실제 흐름을 돌렸을 때의 "측정 종료 10~11초 뒤 두 판본 DONE"과 같은 범위다.
- 여유는 5초 남짓이다. 팀 서버(python:3.11-slim + fonts-nanum)는 글꼴이 적어 보통 더 빠르지만 아직 재지 않았다(워커가 없다, 199 배포 점검). 서버에서 넘으면 보고서 풀을 2개로 늘려 두 판본을 동시에 만드는 것이 먼저인데, 12.4의 "보고서 풀 1개"를 바꾸는 일이라 그때 정한다.
- 견본 12부 모두 금지 표현 0건, 보호자용 용어 설명, 고정 문구 검사를 통과했고, 실린 숫자가 입력의 결과 값과 맞았다(8절 7번과 같은 대조. 기업 서버가 쓸 `reference_from_result`로 기준값을 만들었다).

## 1. 무엇을 재나

`app/report/generate.py`의 `generate_report(입력 JSON, 출력 PDF)` 한 번이다(워커 자식 프로세스가 부르는 함수 그대로).

1. 입력 읽기·검사(`inputs.py`)
2. 수치 표(`numbers.py`, 직전 회차 값과 오차 범위 판정 `judge.py`)
3. 문장(`sentences.py`, 김지윤 템플릿 0.4) → 차트(`charts.py`, matplotlib Figure 2장) → HTML(`html.py`, Jinja2)
4. 검사(`checks.py`: 금지 표현·용어·고정 문구)
5. PDF 변환(`pdf.py`, WeasyPrint)

`generation_ms`는 1~5 전체다. 아래 "단계별"은 같은 입력으로 1~4(HTML)와 5(PDF)를 따로 잰 값이다.

`--pool`은 워커(`app/worker/report.py`)처럼 `ProcessPoolExecutor(max_workers=1)`에 한 경우의 OWNER·VET를 잇따라 넣고 둘이 끝날 때까지의 벽시계 시간을 잰다. DB 읽기·저장소 쓰기·주 반복 주기는 들어 있지 않다.

## 5. 견본 파일

- 저장소에는 넣지 않는다(`backend/docs/*.pdf` 금지, 회사 자료 규칙과 같은 폴더 규칙). 이번 측정의 12부와 입력 JSON, 측정 로그는 조영운 PC `Desktop\문서\보고서_견본_1104\`에 있다(`<경우>_<판본>.pdf`, `<경우>_<판본>.json`, `생성시간_측정_1104.log`).
- 다시 만들기: `python -m scripts.report_samples <폴더>`(PDF), `--html`이면 WeasyPrint 없이 HTML만. 경우 하나만은 `--case follow_up`.

## 6. 남은 것

- 경우 목록은 기업 승인 전 제안이다(계획 문서). 승인되면 이름·순서를 맞추고 이 문서 3절을 고친다.
- 11-05 재측정 오차 범위가 오면 `config/tolerance.yaml`만 바꾸고 follow_up 두 부를 다시 만든다(판정이 바뀔 수 있다).
- 팀 서버에 워커가 생기면 같은 명령으로 서버 값을 재고, 20초를 넘으면 보고서 풀 크기(12.4)를 다시 정한다.
- 김지윤 템플릿 최종본이 오면 TEMPLATE_VERSION을 올리고 12부를 다시 만든다.
