# API 라우팅 컨벤션

nginx와 백엔드 사이의 경계 규약이다. 주소 접두어, 버전, 헬스체크, 인증 없이 열리는 경로처럼 nginx·compose 설정이 기대는 것만 정한다. 이 범위에서는 이 문서가 단일 기준이다. 경로 이름, 필드 형식, 응답 모양, 오류 코드, 인증 방식은 백엔드가 정한다.

## 접두어

```
/api/v1/...
```

- 백엔드의 모든 주소는 `/api/v1`로 시작한다. `/health`, `/metrics`도 예외 없이 `/api/v1/health`, `/api/v1/metrics`다
- nginx는 `/api/`로 시작하는 요청만 백엔드로 넘기고, 나머지는 화면(React 정적 파일)으로 보낸다
- 화면과 API가 한 도메인에 있으므로 CORS 설정은 배포 환경에서 필요 없다

## 버전

- 지금은 `v1` 하나다
- 응답 필드를 빼거나 뜻을 바꾸는 등 호환이 깨지면 `v2`를 새 접두어로 연다. 필드를 더하는 것은 `v1` 안에서 한다
- 새 버전은 nginx location이 아니라 `/api/` 하나로 같이 넘어가므로 nginx 설정은 바뀌지 않는다

## 헬스체크

```
GET /api/v1/health    200 정상 · 503 DB 또는 저장소 이상
```

- 인증 없이 열린다
- Docker healthcheck와 nginx의 `depends_on` 조건이 이 경로와 상태 코드에 기댄다. 경로나 상태 코드를 바꾸려면 compose도 같이 바꾼다

## 인증 없이 열리는 경로

| 경로 | 누가 부르나 | nginx |
| --- | --- | --- |
| `/api/v1/health` | Docker healthcheck | 열어 둔다 |
| `/api/v1/metrics` | 내부 수집기 | 외부에서 닿지 않게 막는다 |

그 밖의 경로는 백엔드가 인증을 처리하고, nginx는 관여하지 않는다.
