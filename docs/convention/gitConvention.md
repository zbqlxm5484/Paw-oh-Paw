# Git 컨벤션

## 흐름

```
이슈 생성 → 브랜치 생성 → 작업, 커밋, 푸시 → MR → 리뷰 1명 이상 → 리뷰어가 머지 → 브랜치 삭제, 이슈 닫기
```

- 이슈는 Jira에 만든다. 작업 단위는 하루 이틀 안에 끝나는 크기
- MR은 작성자 본인이 머지하지 않는다. 리뷰한 사람이 누른다
- 급한 수정으로 기다릴 수 없을 때만 본인이 머지하고 MR에 이유를 남긴다

## 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `master` | 기업 검수용. 중간 검수, 최종 검수 시점에만 갱신 |
| `develop` | 작업 합류 지점. 모든 MR의 대상 |
| `S15P31A404-{Jira번호}-{짧은이름}` | 작업 브랜치. `develop`에서 딴다 |

```
S15P31A404-12-video-upload-api
S15P31A404-27-baseline-eval
```

`develop`을 둘지는 제안이다. 기업이 `master`를 받아 검수하므로 작업 중인 코드와 검수본을 나누려고 넣었다. 팀 회의에서 정한다.

## 올리지 않는 것

- 영상, 사진, 모델 가중치, 정답 라벨 등 기업이 제공한 자료와 그 파생물
- `.env`, 토큰, NAS 접근 정보
- 실험 산출물 (로그, 체크포인트, 결과 영상)

`.gitignore`에 등록한다. 저장소에는 자료를 받아 처리하는 코드만 둔다.
