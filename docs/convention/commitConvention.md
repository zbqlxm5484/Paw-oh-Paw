# 커밋 컨벤션

## 형식

```
<타입>: <제목>
```

- 타입은 영어 소문자, 콜론 뒤에만 공백 한 칸
- 제목은 한글, 영문 기준 50자 이내, 끝에 마침표 없음
- 이모지 없음
- 본문은 제목만으로 이유가 안 드러날 때만 쓴다. 쓸 때는 빈 줄로 띄우고 "무엇"이 아니라 "왜"를 적는다
- 커밋 하나에 문제 하나. 두 가지를 고쳤으면 두 번 커밋한다

## 타입

| 타입 | 언제 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 동작은 같고 구조만 바꿈 |
| `docs` | 문서만 |
| `test` | 테스트 추가와 수정 |
| `chore` | 빌드, 의존성, 설정, .gitignore |
| `style` | 포매팅 등 코드 의미 변화 없음 |
| `rename` | 파일이나 폴더 이름, 위치만 변경 |
| `remove` | 파일 삭제만 |

## 예시

```
feat: 영상 등록 API 추가
fix: 왕복 통과에서 좌우 판정이 뒤집히는 문제 수정
refactor: 평가 스크립트를 함수 단위로 분리
docs: 커밋 컨벤션 추가
chore: requirements.txt 버전 고정
```

## 금지

```
✨feat: 기능 추가        이모지
feat : 기능 추가         콜론 앞 공백
feat: 기능 추가.         마침표
Feat: 기능 추가          대문자
feat: 이것저것 수정      무엇을 했는지 모름
```

## 논의 후보

포지션과 스택이 정해지면 다시 본다.

- `perf`: 결과는 같고 속도, 메모리만 개선 (경량화 작업을 `refactor`와 구분하려면)
- `exp`: 실험 설정과 결과 기록
- `data`: 라벨, 데이터 분할 변경
